# 각자 실행할 명령어

프로젝트 폴더를 통째로 받았다면, **자기 담당 파일만 골라서 한 번 올리면 됩니다.**
어떤 파일이 내 담당인지는 `docs/collab/manifest/push-<본인>.txt` 에 한 줄에 하나씩 적혀 있습니다.

---

## 0. 최초 1회 (전원 공통)

프로젝트 폴더를 압축으로 받았으면 git 이 연결돼 있지 않습니다. 먼저 연결합니다.

```bash
cd ZipSa                                  # 받은 폴더

git init -q                               # .git 이 없을 때만. 이미 있으면 건너뜁니다
git branch -m main

git remote add origin https://github.com/skeey66/ZipSa.git
git fetch origin
git remote -v                             # origin 두 줄이 보이면 성공
git branch -r                             # origin/main origin/backend origin/frontend origin/ai
```

> `fatal: remote origin already exists` → 이미 연결돼 있습니다. 주소만 바꾸려면
> `git remote set-url origin https://github.com/skeey66/ZipSa.git`

> `remote: Permission ... denied` → 오너가 **Settings → Collaborators** 에서 Write 권한으로
> 초대해야 push 할 수 있습니다.

### .env 만들기

```bash
cp .env.example .env
openssl rand -base64 48                   # 출력값을 .env 의 JWT_SECRET 에 붙여넣기
```

`.env` 의 `POSTGRES_PASSWORD` 도 아무 값으로 채웁니다. **`.env` 는 절대 커밋하지 않습니다.**

### `-f` 를 붙이는 이유

각자 **프로젝트 전체**를 받았기 때문에, 앞사람이 이미 올린 파일이 내 폴더에도 똑같이 있습니다.
그냥 `git checkout` 하면 git 이 막습니다.

```
error: The following untracked working tree files would be overwritten by checkout
```

내용이 같은 파일이므로 `-f` 로 덮어쓰면 됩니다. **내 담당 파일은 건드리지 않습니다.**
단, 받은 뒤 그 파일을 직접 고쳤다면 그 수정분은 사라지니 먼저 백업하세요.

## 1. 백엔드 담당 — `backend` 브랜치

### BE1 — 인증·회원 · 커뮤니티·대출 (56개) · 제일 먼저

```bash
git fetch origin
git checkout -f -B backend origin/backend

git add --pathspec-from-file=docs/collab/manifest/push-BE1.txt
git status --short                      # 56개인지, .env 가 없는지 확인

git commit -m "feat(auth,community): 인증·회원 API 와 커뮤니티·대출 API"
git push origin backend
```

### BE2 — 정책·뉴스 · 공공임대·실거래가 · 크롤러 (69개) · BE1 다음

```bash
git fetch origin
git checkout -f -B backend origin/backend    # BE1 이 올린 것까지 받은 상태가 됩니다

git add --pathspec-from-file=docs/collab/manifest/push-BE2.txt
git status --short

git commit -m "feat(policy,housing): 정책·뉴스 API 와 공공임대·실거래가 API, 수집 크롤러"
git push origin backend
```

### 백엔드 실행 확인

```bash
docker compose up -d db
cd backend
set -a && . ../.env && set +a           # 빼먹으면 기동 실패
./gradlew bootRun                        # Started ZipsaApplication → localhost:8080
```

## 자주 나는 문제

**push 가 거절될 때**

```
! [rejected] backend -> backend (fetch first)
```

앞사람이 먼저 올렸다는 뜻입니다.

```bash
git pull --rebase origin backend
git push origin backend
```

**`git add .` 는 쓰지 마세요.** 프로젝트 파일을 통째로 받았기 때문에 남의 담당 파일까지 전부 올라갑니다.
반드시 `--pathspec-from-file` 로 자기 manifest 만 올립니다.

**올리기 전 확인**

```bash
git status --short                      # 내 manifest 개수와 같은지, .env 가 없는지
git diff --cached --name-only | wc -l
```
