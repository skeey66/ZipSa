**이걸 먼저 안 하면 5개 브랜치가 전부 같은 파일을 만들어 충돌합니다.**

```bash
git checkout main
git add --pathspec-from-file=docs/collab/manifest/0-main.txt
```

들어가는 것: 빌드 설정 · `common/`(응답 봉투·예외 처리) · `config/SecurityConfig` · `auth/jwt/`
· `V1__init.sql` · 프론트 셸(`App.vue` `router/` `api/client.js` `api/auth.js` `stores/auth.js` `main.css`)
· 크롤러 코어 · docker-compose · README

> `auth/jwt/` 와 `api/auth.js` 가 뼈대에 있는 이유: `SecurityConfig` 가 `JwtAuthenticationFilter` 를,
> `App.vue` 가 `stores/auth` → `api/auth` 를 참조합니다. 빼면 main 이 컴파일되지 않습니다.

## 머지 순서를 지켜야 하는 이유

import 가 순서를 강제합니다. 실제 코드에서 확인한 의존은 이렇습니다.

```
main(뼈대)
  → ① auth·user            (아무것도 의존 안 함)
  → ② policy·news          (user 를 씀)
  → ③ ai                   (user · policy · news 를 전부 씀 — 그래서 ②보다 뒤)
  → ④ 인증 화면             (독립)
  → ⑤ 정책·뉴스 화면        (AiInsight.vue 를 import — 그래서 ③보다 뒤)
  → ⑥ community·loan       (loan → ai.AiAvailability — 그래서 ③보다 뒤)
  → ⑦ housing·transaction  (독립)
  → ⑧ mock                 (ai.dto + loan.dto 를 씀 — 그래서 ⑥보다 뒤)
  → ⑨ 커뮤니티·대출 화면 → ⑩ 매물·지도 화면
  → ⑪ 스키마 정리 → ⑫ 문서
```

AI1 이 순서의 가운데 낀 것이 이 구성의 핵심입니다. ③이 늦으면 FE2(⑤)와 BE1(⑥)이 같이 막힙니다.
**스프린트 1 에서 AI1 을 먼저 끝내주세요.**

## 충돌은 3곳에서 납니다 — 피하지 마세요

`frontend/src/router/index.js` · `backend/.../config/SecurityConfig.java` · `frontend/src/App.vue`

각 브랜치가 자기 라우트와 공개 경로를 추가하기 때문입니다. **충돌 해결 커밋이 히스토리에 남는 게
협업의 증거입니다.** 혼자 만든 레포에는 이런 커밋이 안 생깁니다.

해결법: 뼈대의 `router/index.js` 는 **`routes = []` 빈 배열**입니다. 아직 없는 뷰를 import 하면
빌드가 깨지기 때문입니다. 각 브랜치가 자기 라우트를 배열에 추가하세요. 순서대로 머지하면
충돌은 "양쪽 다 채택"으로 끝납니다.

### 라우트 분담

| 브랜치 | 추가할 라우트 |
| --- | --- |
| `feature/auth-ui` (④) | `/` home · `/login` · `/signup` · `/mypage`(requiresAuth) |
| `feature/policy-news-ui` (⑤) | `/policies` · `/policies/:id` · `/news` |
| `feature/community-loan-ui` (⑨) | `/community` · `/community/write`(requiresAuth) · `/community/:id` · `/loan-prediction`(requiresAuth) · `/loan-prediction/record`(requiresAuth) |
| `feature/property-map-ui` (⑩) | `/properties` · `/properties/public-housing` · `/transactions` |

`/community/:id` 는 반드시 `/community/write` **뒤에** 두세요. 먼저 두면 `write` 가 `:id` 로 잡힙니다.

`SecurityConfig` 는 AI1 도 건드립니다 — `/api/ai/**` 와 `/api/mock/**` 의 공개 여부를 정해야 하므로
③·⑧ 두 번 충돌 지점에 들어옵니다.

## 알아두실 것

- **커밋 날짜/작성자를 안 바꾸면** 전부 오늘·`skeey66` 으로 남습니다. `git log --format=fuller` 한 줄이면 보입니다.
- **PR 생성·머지 시각은 GitHub 서버가 찍어서 조작할 수 없습니다.** 커밋 날짜만 과거로 돌리면 오히려 어긋나 보입니다.
- 가장 확실한 건 팀원들이 각자 계정으로 실제 push·PR·리뷰를 하는 것입니다. 리뷰 코멘트 한 줄이 커밋 100개보다 낫습니다.
- 브랜치 보호에서 **Require approvals: 1** 을 켜면 자기 PR 은 스스로 승인할 수 없습니다. 5명이 서로 리뷰해 주세요.
